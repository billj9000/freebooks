## Running the Application

FreeBooks is a PHP/MySQL web application with no build step. It can be deployed directly to any PHP-capable web server (Apache/Nginx) with MySQL/MariaDB, or via Docker using the companion **freebooks-docker** repository.

In either case, the `trunk/` directory is deployed as the web root. The other top-level directories are optional — `extensions/` contains optional components (additional modules, payment methods, shipping methods, language packs, etc.) that may be selectively copied into the installation.

After deploying `trunk/`, visit `/install/` in a browser to run the web-based installer, which creates `trunk/includes/configure.php` and seeds the database.

There is no `package.json`, Makefile, or automated test runner. Manual test procedures are in `TestProcedures/` as ODS spreadsheets.

PHP dependencies are managed via Composer (`trunk/composer.json`). The `trunk/vendor/` directory is **intentionally committed to the repository** so that deployment requires no build step — just copy `trunk/` to the web root as with all other vendored assets (jQuery, Bootstrap, etc.). To add or update a package, run `composer update` locally and commit the resulting changes to `vendor/` and `composer.lock`.

## Configuration

Two configuration files are required at runtime (neither is in version control):

- `trunk/includes/configure.php` — server-level DB credentials and path constants, generated by the web installer
- `trunk/my_files/{company_name}/config.php` — per-company DB credentials

Runtime settings (feature flags, UI preferences, locale) are stored in the `pb_configuration` database table, not in files.

## Architecture

### Request Flow

Every request enters through `trunk/index.php`, which:
1. Loads `includes/application_top.php` — bootstraps the session, config, DB connection, and language strings
2. Authenticates the user (redirects to phreedom login if not authenticated)
3. Dispatches to `modules/{module}/pages/{page}/pre_process.php` — business logic and form handling
4. For AJAX requests (`?page=ajax&op={op}`), loads `modules/{module}/ajax/{op}.php` and exits
5. Renders `modules/{module}/pages/{page}/template_main.php` inside `includes/template_index.php`
6. Closes with `includes/application_bottom.php`

URL parameters drive routing: `?module=phreebooks&page=journal&jID=12`

### Module Structure

Every module under `trunk/modules/` follows the same layout:

```
{module}/
├── config.php          # Module metadata, menu definitions, TABLE_* constants, security IDs
├── defaults.php        # Module-level PHP constants
├── pages/{page}/
│   ├── pre_process.php     # Business logic; reads $_GET/$_POST, writes to $messageStack
│   ├── template_main.php   # HTML output
│   └── js_include.php      # Page-specific JavaScript
├── ajax/               # One file per AJAX op, returns JSON or HTML fragment
├── classes/            # Reusable business-logic classes for this module
├── functions/          # Helper functions
├── language/en_us/     # Translatable strings
└── custom/             # Drop-in overrides (same sub-structure); loaded instead of originals when present
```

### Core Modules

| Module | Responsibility |
|---|---|
| **phreedom** | Authentication, user/role management, company management, admin panel |
| **phreebooks** | General ledger, journals (J1–J22), orders, invoices, bank reconciliation, reports |
| **contacts** | Customers, vendors, pricing |
| **inventory** | SKU/stock management, warehouses |
| **phreeform** | Report designer and print engine |
| **phreepos** | Point of Sale |
| **payment** | Payment method plugins |
| **shipping** | Shipping method plugins |
| **phreehelp** | Integrated help system |

Optional extension modules are available in `extensions/Modules/` and are copied into `trunk/modules/` to activate.

### Key Shared Code

- `trunk/includes/common_functions.php` — ~100KB of global helper functions (`db_perform()`, `gen_redirect()`, `html_href_link()`, `gen_pull_language()`, `gen_calculate_period()`, etc.)
- `trunk/includes/common_classes.php` — Core UI and utility classes: `toolbar`, `messageStack`, `splitPageResults`, `currencies`, `encryption`
- `trunk/includes/db/mysql/query_factory.php` — Database abstraction layer (`queryFactory` class); wraps MySQL with transaction support and a result-cursor API (`MoveNext()`, `EOF()`)

### Customization

The `custom/` subdirectory within any module is a drop-in override layer. If `modules/{module}/custom/pages/{page}/pre_process.php` exists, it is loaded instead of the standard file. This allows local modifications without patching core files.

## File Header Policy

Every PHP and CSS file we touch or create must carry the standard FreeBooks header block. The copyright lines differ depending on whether the file originated in PhreeBooks 3.7.1 or was written by us.

**Files that existed in the initial PhreeBooks 3.7.1 commit** (`d55b74c`) — use both copyright lines:

```
// +-----------------------------------------------------------------+
// |                          FreeBooks ERP                          |
// +-----------------------------------------------------------------+
// | Copyright(c) 2026 Bill Jones                                    |
// | Portions Copyright(c) 2008-2014 PhreeSoft                       |
// +-----------------------------------------------------------------+
// | This program is free software: ...                              |
// ...
// +-----------------------------------------------------------------+
```

**Files we created** (not present in `d55b74c`) — Bill Jones copyright only:

```
// +-----------------------------------------------------------------+
// |                          FreeBooks ERP                          |
// +-----------------------------------------------------------------+
// | Copyright(c) 2026 Bill Jones                                    |
// +-----------------------------------------------------------------+
// | This program is free software: ...                              |
// ...
// +-----------------------------------------------------------------+
```

To check whether a file existed in the initial PhreeBooks commit, run:
```
git diff --name-status d55b74c HEAD -- <path>
```
`A` = added by us (Bill Jones only); `M` = modified from PhreeBooks (both lines).

CSS files use the same block with `/* * */` comment style instead of `//`.

### Security Model

- Session-based authentication (`$_SESSION['admin_id']`, `$_SESSION['company']`)
- Per-page permission checks via `validate_user($security_id)` using role definitions in phreedom
- Multi-company isolation: each company has its own database (credentials in `my_files/{company}/config.php`)
