# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Running the Application

FreeBooks is a PHP/MySQL web application with no build step. It can be deployed directly to any PHP-capable web server (Apache/Nginx) with MySQL/MariaDB, or via Docker using the companion **freebooks-docker** repository.

In either case, the `trunk/` directory is deployed as the web root. The other top-level directories are optional — `extensions/` contains optional components (additional modules, payment methods, shipping methods, language packs, etc.) that may be selectively copied into the installation.

After deploying `trunk/`, visit `/install/` in a browser to run the web-based installer, which creates `trunk/includes/configure.php` and seeds the database.

There is no `package.json`, Makefile, or automated test runner. Manual test procedures are in `TestProcedures/` as ODS spreadsheets.

PHP dependencies are managed via Composer (`trunk/composer.json`). The `trunk/vendor/` directory is **intentionally committed to the repository** so that deployment requires no build step — just copy `trunk/` to the web root as with all other vendored assets (jQuery, Bootstrap, etc.). To add or update a package, run `composer update` locally and commit the resulting changes to `vendor/` and `composer.lock`.

## Configuration

Two configuration files are required at runtime (neither is in version control):

- `trunk/includes/configure.php` — server-level DB credentials and path constants, generated by the web installer
- `trunk/my_files/{company_name}/config.php` — per-company DB credentials

Runtime settings (feature flags, UI preferences, locale) are stored in the `pb_configuration` database table, not in files.

## Architecture

### Request Flow

Every request enters through `trunk/index.php`, which:
1. Loads `includes/application_top.php` — bootstraps the session, config, DB connection, and language strings
2. Authenticates the user (redirects to phreedom login if not authenticated)
3. Dispatches to `modules/{module}/pages/{page}/pre_process.php` — business logic and form handling
4. For AJAX requests (`?page=ajax&op={op}`), loads `modules/{module}/ajax/{op}.php` and exits
5. Renders `modules/{module}/pages/{page}/template_main.php` inside `includes/template_index.php`
6. Closes with `includes/application_bottom.php`

URL parameters drive routing: `?module=phreebooks&page=journal&jID=12`

### Module Structure

Every module under `trunk/modules/` follows the same layout:

```
{module}/
├── config.php          # Module metadata, menu definitions, TABLE_* constants, security IDs
├── defaults.php        # Module-level PHP constants
├── pages/{page}/
│   ├── pre_process.php     # Business logic; reads $_GET/$_POST, writes to $messageStack
│   ├── template_main.php   # HTML output
│   └── js_include.php      # Page-specific JavaScript
├── ajax/               # One file per AJAX op, returns JSON or HTML fragment
├── classes/            # Reusable business-logic classes for this module
├── functions/          # Helper functions
├── language/en_us/     # Translatable strings
└── custom/             # Drop-in overrides (same sub-structure); loaded instead of originals when present
```

### Core Modules

| Module | Responsibility |
|---|---|
| **phreedom** | Authentication, user/role management, company management, admin panel |
| **phreebooks** | General ledger, journals (J1–J22), orders, invoices, bank reconciliation, reports |
| **contacts** | Customers, vendors, pricing |
| **inventory** | SKU/stock management, warehouses |
| **forms** | Report and form designer, print engine, and the document catalog |
| **phreepos** | Point of Sale |
| **payment** | Payment method plugins |
| **shipping** | Shipping method plugins |
| **phreehelp** | Integrated help system |

Optional extension modules are available in `extensions/Modules/` and are copied into `trunk/modules/` to activate.

### Key Shared Code

- `trunk/includes/common_functions.php` — ~100KB of global helper functions (`db_perform()`, `gen_redirect()`, `html_href_link()`, `gen_pull_language()`, `gen_calculate_period()`, etc.)
- `trunk/includes/common_classes.php` — Core UI and utility classes: `toolbar`, `messageStack`, `splitPageResults`, `currencies`, `encryption`
- `trunk/includes/db/mysql/query_factory.php` — Database abstraction layer (`queryFactory` class); wraps MySQL with transaction support and a result-cursor API (`MoveNext()`, `EOF()`)

### Customization

The `custom/` subdirectory within any module is a drop-in override layer. If `modules/{module}/custom/pages/{page}/pre_process.php` exists, it is loaded instead of the standard file. This allows local modifications without patching core files.

### UI Standards for New Pages

All new pages must use the **FreeBooks Bootstrap/htmx theme**. Concretely:

- Use Bootstrap classes for layout and components (grid, cards, modals, buttons, tables)
- Use htmx attributes (`hx-get`, `hx-post`, `hx-target`, `hx-swap`, etc.) for dynamic interactions instead of writing custom jQuery AJAX calls
- The existing shipping estimator modal (`trunk/modules/phreebooks/pages/orders/`) is a reference implementation of this pattern

Do not introduce new jQuery-only UI patterns or custom CSS frameworks on new pages.

### Bootstrap Page Conversion Rules

When converting an existing jQuery UI page to Bootstrap, follow these rules. Detailed notes are in memory file `reference_phreebooks_tab_conversion.md`.

**Every converted page must:**
- Set `$use_bootstrap_nav = true;` in `pre_process.php`
- Every `fb-card` must have `<div class="card-header py-1 fb-widget-header">Title</div>` — gives the blue gloss-wave header (`#a6c9e2` border, `#fcfdfd` body)
- Use `table-dark` on `<thead>` — freebooks.css overrides this to the gloss-wave gradient
- Use Bootstrap `form-control`/`form-select` on inputs in **form/detail cards** (transaction details, payment fields, etc.)

**Address/contact blocks** (stacked name/address inputs with clearField placeholders):
- Use **plain inputs with `size=` attributes** — no `form-control` class
- Use plain `<select>` with `style="width:100%"` — no `form-select` class
- This matches the orders page and makes placeholder text look like labels rather than form fields

**Fieldset-style sections** (grouped content with a floating title in the border):
- Use `<div class="fb-fieldset mb-2">` + `<div class="fb-fieldset-legend">Title</div>` — do **not** use native `<fieldset>`/`<legend>` elements
- `fb-fieldset` and `fb-fieldset-legend` are defined in `trunk/ext/bootstrap5/freebooks.css`
- This approach is CSS-only so it can be restyled per theme; native `<fieldset>` fights CSS overrides
- Use for standalone utility/tool pages (e.g. admin_tools); use `fb-card`/`fb-widget-header` for dashboard-style panels with a filled header bar

**Tab pages** — see the tab conversion checklist in the memory reference.

### Documenting in the Help Module

User-facing documentation lives in the **phreehelp** manual. When a change affects how users interact with FreeBooks, add or update a manual topic.

- **Content location:** `modules/{module}/language/en_us/manual/{chNN-Chapter}/{NN-Topic}.html` — plain HTML topic files grouped into chapter subdirectories (`ch01-Introduction` … `ch20-Glossary`). Put a topic in the module it belongs to (e.g. login/accounts → `phreedom/…/ch06-UsersSecurity`).
- **Required `<head>` meta tags:** `doc_pos` (dotted table-of-contents position, e.g. `06.04`; a topic nests under its parent, so `06.04` sits under the chapter landing page whose `doc_pos` is `06`) and `doc_title`. Optional: `doc_index_1`/`doc_index_2` (left-hand index, `Group.Label`) and `doc_glossary_N` (`term:definition`). The `<title>` and the stripped body text feed manual search.
- **Model new topics on an existing sibling** (e.g. `ch06-UsersSecurity/03-Passkeys.html`) for meta layout, tone, and the Related Topics footer. Keep `doc_pos` unique, and add a link from the chapter landing page's Related Topics list.
- **Locale fallback:** the scanner uses `language/{locale}/manual` for a module if that directory exists, else falls back to `en_us` for that module's *entire* manual. In practice only `en_us` has content — add topics there; do **not** create partial per-locale manual dirs (that would hide all the en_us topics for that module in that locale).
- **A reindex is required to see changes.** The TOC and search are indexed into the phreehelp table (`TABLE_PHREEHELP`) by `synchronize()`, which runs only when the `PHREEHELP_FORCE_RELOAD` runtime config is `1`; a new/edited HTML file does **not** appear until then. Fresh installs and module updates set the flag automatically; otherwise set `PHREEHELP_FORCE_RELOAD=1` (it resets to `0` after the next Help open reindexes). Applies on every deploy target, including production.
- **Context-sensitive help:** a page wires its toolbar Help button with `$toolbar->add_help('NN.NN')`, where the argument is the target topic's `doc_pos`. Pre-auth pages (login/password reset) have no toolbar, so their topics are reached via browse/search only.
- **Manual HTML files are content, not source code** — they do **not** take the FreeBooks copyright header block (see File Header Policy); match the existing topic files.

## No Private Names in Anything Committed

Everything in this repository is public. Git history is permanent — a name committed once stays
recoverable even after it is removed — so the check happens **before** the commit, not after.

Never commit private or identifying details, in **any** file type: source, comments, documentation,
help topics, dev tools, test fixtures, commit messages. Specifically:

- **Company and database names** of real installations. The Forms design doc and its tools refer to
  two companies as **`demo`** (a stock installation with demonstration data) and **`production`**
  (a real installation, large volume, carrying customised definitions). Use that pairing, or a
  similarly neutral one, rather than the actual company directory names.
- **Customer, vendor, employee and contact names**, real SKUs, invoice or order numbers, addresses,
  telephone numbers and email addresses taken from live data. Invent plainly fictional stand-ins.
- **Hostnames, IP addresses, container names, absolute local paths, credentials and API keys.**
  Use a placeholder — `<c>` for the container name, as the existing tool docs already do.

This applies to *measured* output too, which is where it usually slips in: a verification tool's
sample rows, a quoted error message, a worked example in a design document. Quote the shape and the
figures, not the identities.

**The author is not private.** Copyright statements, licence blocks, the `Copyright(c) 2026 Bill
Jones` line required by the File Header Policy below, authorship credits, and the git committer
identity are all deliberate attributions and must stay exactly as they are. Removing them would
misstate authorship and, for the licence text, breach the terms. The same goes for upstream authors
in third-party files.

Scratch files, throwaway scripts and Artifacts are not committed and are not covered by this — but
anything under `docs/`, `trunk/` or `extensions/` is.

## File Header Policy

This policy applies to **FreeBooks' own source files only** — see "Third-party code" below for the exclusion.

Every PHP and CSS file we touch or create must carry the standard FreeBooks header block. The copyright lines differ depending on whether the file originated in PhreeBooks 3.7.1 or was written by us.

**Files that existed in the initial PhreeBooks 3.7.1 commit** (`22ec09f`) — use both copyright lines:

```
// +-----------------------------------------------------------------+
// |                          FreeBooks ERP                          |
// +-----------------------------------------------------------------+
// | Copyright(c) 2026 Bill Jones                                    |
// | Portions Copyright(c) 2008-2014 PhreeSoft                       |
// +-----------------------------------------------------------------+
// | This program is free software: ...                              |
// ...
// +-----------------------------------------------------------------+
```

**Files we created** (not present in `22ec09f`) — Bill Jones copyright only:

```
// +-----------------------------------------------------------------+
// |                          FreeBooks ERP                          |
// +-----------------------------------------------------------------+
// | Copyright(c) 2026 Bill Jones                                    |
// +-----------------------------------------------------------------+
// | This program is free software: ...                              |
// ...
// +-----------------------------------------------------------------+
```

To check whether a file existed in the initial PhreeBooks commit, run:
```
git diff --name-status 22ec09f HEAD -- <path>
```
`A` = added by us (Bill Jones only); `M` = modified from PhreeBooks (both lines).

CSS files use the same block with `/* * */` comment style instead of `//`.

### Third-party code — do NOT add the header

Vendored third-party libraries carry their own copyright and license headers. **Never add, replace, or edit the copyright block in these files, even when we modify them** — asserting FreeBooks/Bill Jones copyright over someone else's LGPL/MIT/GPL code misstates authorship and can breach the upstream license. Leave the existing upstream header exactly as-is and change only the code.

This covers, among others:

| Path | Upstream |
|---|---|
| `trunk/vendor/` | Composer packages (PHPMailer, Twig, BoxPacker, TCPDF, …) |
| `trunk/ext/` | Bootstrap, htmx, and other bundled front-end assets |
| `trunk/jodit/` | Jodit editor |
| `extensions/Modules/zencart/ZenCartFiles/` | ZenCart's own files (run on the ZenCart side) |
| `extensions/Modules/doc_ctl/includes/jstree/` | jsTree |

The `22ec09f` provenance check above does **not** apply here: these files were present at the initial import, but that makes them vendored PhreeBooks dependencies, not PhreeBooks code we inherited. If a file has an upstream author/license banner of its own, treat it as third-party regardless of what the git history says.

`trunk/ext/bootstrap5/freebooks.css` is the exception in that list — it is our own stylesheet living alongside vendored assets, so it *does* take the standard header.

### Security Model

- Session-based authentication (`$_SESSION['admin_id']`, `$_SESSION['company']`)
- Per-page permission checks via `validate_user($security_id)` using role definitions in phreedom
- Multi-company isolation: each company has its own database (credentials in `my_files/{company}/config.php`)
