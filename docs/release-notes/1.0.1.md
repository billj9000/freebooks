# FreeBooks 1.0.1

FreeBooks 1.0.1 is a security and maintenance release. Its container image is built on PHP 8.5.12,
which fixes two critical PHP flaws that a single request, with no login, can use to run code on the
server. It also corrects how tax is shown and posted on documents with several tax authorities and
at the point of sale, and fetches Parcelforce commercial invoices with the label.

**Anyone running the 1.0.0 image should update now.** Anyone running FreeBooks on their own PHP
should make sure that PHP has the fix (see below).

## Security

- **PHP 8.5.12 in the container image** (#125). PHP 8.5.12 fixes CVE-2026-109618 and
  CVE-2026-109619 ([CERT-EU advisory 2026-018](https://cert.europa.eu/publications/security-advisories/2026-018)):
  memory corruption in out-of-memory handling and stale request state, each reachable by a single
  unauthenticated request before any FreeBooks code runs. Every PHP web server is affected, and
  Apache `mod_php`, which the image uses, is rated highest risk. The image also switches off
  session upload progress and fatal error backtraces, the advisory's mitigations for the confirmed
  paths; FreeBooks uses neither.

  Without Docker, FreeBooks needs a PHP with the fix: **8.5.12, 8.4.27, 8.3.36 or 8.2.35** or later,
  or a distribution package that backports it. Until then, keep the server off the internet.

## Fixes

- **Tax on the screen matches the tax posted** (#118). The order and point-of-sale screens worked out
  tax on each rate's combined percentage, while the ledger rounds each tax authority separately.
  With a rate of several authorities the two could differ by a penny or more. The screens now work
  tax out the ledger's way.
- **Point-of-sale order discounts reduce the tax** (#121). With tax after the discount, the default,
  the server taxed the full amount and posted the difference to the rounding account, so the tax
  account was overstated. A percentage discount off the total no longer discounts the tax twice.
- **Till expenses post their tax per authority** (#122). An expense paid out of a till posted the
  screen's tax figure as one row, sometimes to the wrong account or to none. The ledger now works the
  tax out from the rate, one row per authority, and the screen shows the same figure. An expense type
  that does not use tax posts none.

## Shipping

- **Parcelforce commercial invoice** (#124). For Parcelforce Europriority and GlobalPriority labels,
  FreeBooks also fetches the commercial invoice Click & Drop writes and saves it as its own PDF, so
  the label goes to the label printer and the invoice prints on A4. Both open in the label viewer and
  again from the Shipping Manager. Click & Drop writes the invoice only when the trading name has a
  logo and signature (Click & Drop → Settings → Trading names).

## Docker

- A cron file added under `/etc/cron.d/` must name PHP by its full path, `/usr/local/bin/php`: such a
  file does not see the image crontab's search path. The README's example does so (#120).

## Upgrading

Replace the code (or pull the new image) and log in. The first login records version 1.0.1; there
are no database changes. With Docker Compose, `ghcr.io/billj9000/freebooks:1.0` and `latest` now
point at 1.0.1.
