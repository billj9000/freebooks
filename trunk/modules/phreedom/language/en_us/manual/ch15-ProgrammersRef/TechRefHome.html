Programmer's Reference

This chapter is for developers working on FreeBooks itself — extending a module, adding a page, or building an integration. It's a tour of the codebase, not an end-user guide.

Request flow

Every request enters through trunk/index.php, which:

  1. Loads includes/application_top.php — bootstraps the session, configuration, database connection, and language strings.
  2. Authenticates the user, redirecting to the login page if not authenticated.
  3. Dispatches to modules/{module}/pages/{page}/pre_process.php for business logic and form handling.
  4. For AJAX requests (?page=ajax&op={op}), loads modules/{module}/ajax/{op}.php and exits.
  5. Renders modules/{module}/pages/{page}/template_main.php inside includes/template_index.php.
  6. Closes with includes/application_bottom.php.

URL parameters drive routing — for example ?module=phreebooks&page=journal&jID=12.

Module structure

Every module under trunk/modules/ follows the same layout:

config.php (module metadata, menu definitions, TABLE_* constants, security IDs), defaults.php (module-level constants), pages/{page}/ (pre_process.php, template_main.php, js_include.php), ajax/ (one file per AJAX op), classes/, functions/, language/{locale}/ (including this manual, under language/{locale}/manual/), and custom/.

Key shared code

  • includes/common_functions.php — global helper functions: db_perform(), gen_redirect(), html_href_link(), gen_pull_language(), gen_calculate_period(), html_icon(), and many more.
  • includes/common_classes.php — core UI and utility classes: toolbar, messageStack, splitPageResults, currencies, encryption.
  • includes/db/mysql/query_factory.php — the queryFactory database abstraction class, wrapping PDO with transaction support (transStart()/transCommit()/transRollback()) and a result-cursor API (Execute(), MoveNext(), EOF(), fields).

Always build SQL through $db->prepare_input() or the db_input() helper when interpolating user input into a query — neither db_prepare_input() nor db_perform()'s array binding escape a raw string dropped directly into a hand-built SELECT/WHERE clause.

Customization: the custom/ override layer

The custom/ subdirectory within any module is a drop-in override layer. If modules/{module}/custom/pages/{page}/pre_process.php exists, it is loaded instead of the standard file, mirroring the same sub-structure as the module itself. This allows site-specific modifications without patching core files, and is also how optional extensions (see extensions/Modules/ in the repository) hook into existing pages — for example adding an extra toolbar button or menu entry.

Security model

  • Session-based authentication ($_SESSION['admin_id'], $_SESSION['company']).
  • Per-page permission checks via validate_user($security_id), using role definitions maintained in the phreedom module.
  • Multi-company isolation: each company has its own database, with credentials in my_files/{company}/config.php.

Extending the report/print engine

New modules that need printable output (invoices, labels, custom reports) plug into the existing report designer rather than building their own PDF generation — see Reports and Forms.
