OAuth2 Setup (Gmail / Office 365)

Google and Microsoft have disabled password-based SMTP authentication for many accounts and now require OAuth2. This page explains how to register an application with each provider and configure FreeBooks to use it.

The OAuth2 flow redirects the user's browser through the provider's consent screen — the provider never contacts your server directly — so it works correctly even when FreeBooks is hosted on localhost.

Overview of steps

  1. Register an application with your provider (Google Cloud Console or Azure).
  2. Enter the Client ID, Client Secret, and other settings in General Admin › Email.
  3. Click Authorise with Provider. A consent window opens.
  4. Sign in with the sending mailbox account and grant access.
  5. The refresh token is stored automatically. Save the form.

The redirect URI to register with your provider is:
http(s)://<your-server>/oauth2_callback.php

Google (Gmail)

1. Create a project and OAuth credentials

  1. Go to Google Cloud Console and sign in with a Google account that has access to the sending mailbox (or any Google account — you will grant access to the mailbox during authorisation).
  2. Create a new project (or select an existing one).
  3. In the left menu go to APIs & Services › OAuth consent screen.
    • User type: External (unless you have a Google Workspace organisation).
    • Fill in the App name, user support email, and developer contact email.
    • No scopes need to be added on this screen; click through to Save and Continue.
    • Under Test users, add the Gmail address you will send from.
  4. Go to APIs & Services › Credentials › Create Credentials › OAuth client ID.
    • Application type: Web application.
    • Under Authorised redirect URIs, add your callback URL, e.g.
      http://localhost/oauth2_callback.php
    • Click Create.
  5. Copy the Client ID and Client secret.

2. Enable the Gmail API

Go to APIs & Services › Library, search for Gmail API, and click Enable.

3. Configure FreeBooks

  • Transport: SMTP with OAuth2
  • SMTP server: smtp.gmail.com
  • Port: 587   Encryption: STARTTLS
  • Provider: Google (Gmail)
  • Client ID / Client secret: paste from step 1.
  • Authorised email address: the Gmail address you will send from.
  • Click Authorise with Provider and complete the consent screen.
  • Save the form.

Note: While the app is in Testing mode on the consent screen, only the test users you listed can authorise it. For a production deployment, submit the app for Google review or keep it in testing with your address added as a test user.

Microsoft Office 365

1. Register an application in Azure

  1. Go to the Azure portal › App registrations and sign in with an account that has permission to register applications.
  2. Click New registration.
    • Name: e.g. FreeBooks Mail.
    • Supported account types: choose Accounts in this organisational directory only for a single-tenant organisation, or Accounts in any organisational directory and personal Microsoft accounts for multi-tenant / personal accounts.
    • Redirect URI: platform Web, URI e.g.
      http://localhost/oauth2_callback.php
    • Click Register.
  3. On the app overview page, copy the Application (client) ID and Directory (tenant) ID.
  4. Go to Certificates & secrets › New client secret. Add a description, choose an expiry, and copy the generated secret value immediately (it is only shown once).

2. Add SMTP.Send permission

  1. Go to API permissions › Add a permission › APIs my organisation uses and search for Office 365 Exchange Online.
  2. Choose Delegated permissions and tick SMTP.Send.
  3. Click Add permissions.
  4. If your tenant requires it, click Grant admin consent.

3. Enable SMTP AUTH for the mailbox

By default, Microsoft 365 disables SMTP AUTH per mailbox. A Microsoft 365 administrator must enable it for the sending account:

Set-CASMailbox -Identity user@example.com -SmtpClientAuthenticationDisabled $false

Or enable it tenant-wide in the Microsoft 365 admin centre under Settings › Org settings › Modern authentication.

4. Configure FreeBooks

  • Transport: SMTP with OAuth2
  • SMTP server: smtp.office365.com
  • Port: 587   Encryption: STARTTLS
  • Provider: Microsoft (Office 365 / Outlook)
  • Client ID: Application (client) ID from step 1.
  • Client secret: secret value from step 1.
  • Tenant: Directory (tenant) ID from step 1, or common for multi-tenant / personal accounts.
  • Authorised email address: the Office 365 address you will send from.
  • Click Authorise with Provider and complete the Microsoft login.
  • Save the form.

Token expiry

Refresh tokens are long-lived but can expire if unused for 90 days (Microsoft default) or if the user changes their password. If email sending fails with an authentication error, click Authorise with Provider again to obtain a new refresh token.
