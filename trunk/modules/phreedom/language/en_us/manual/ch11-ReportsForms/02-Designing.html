Designing Reports and Forms

Editing or creating a report or form opens the designer, which requires a higher permission level than simply running one. A new report or form starts from a data source, then adds filters and either a column layout (Reports) or a positioned layout (Forms).

Data source

Every report or form is built on a SQL query: pick the database table(s) it draws from, and how they join together if more than one table is used (standard join types are available — inner, left, right, cross, and their "outer"/"natural" variants). This is how a report can, for example, combine invoice header and line-item data in one query.

Criteria (filters)

Any field in the data source can be exposed as a run-time filter. Depending on the field, the filter can be a simple choice (All/Yes/No, All/Active/Inactive, All/Printed/Unprinted), a range or exact match, or a raw comparison (equals, not equals, in a list, less than, greater than, is/is not null). Date fields can instead use a fiscal-period-aware date range, tied into FreeBooks' accounting period system rather than plain calendar dates.

Designing a Report

For a Report, you choose which fields become columns: label, visibility, column width, whether it starts a new column group, and any per-field processing (see below). You can also define grouping (break the report into sections by a field's value, optionally starting a new page per group, with subtotals) and sorting. Separate font, size, color, and alignment settings apply to the heading, the two title lines, the filter description, the data rows, and the totals row.

Designing a Form

A Form is different: instead of a column list, you place elements at exact positions on a page, like a page layout tool. Available building blocks include:

  • A single data field, a repeating data block, or a data table (for line items).
  • A running total.
  • Letter Template / Letter Data blocks, for building mail-merge style letters as a Form.
  • Fixed text, an image (uploaded or from an image library), or a dynamic image linked per-record.
  • Rectangles and lines, for visual structure.
  • Company data (your own company's name/address/logo), as a single field or a block.
  • A page number.
  • A bar code — Code 39 and variants, Interleaved 2 of 5, Code 128 (A/B/C), EAN-13, UPC-A, POSTNET, or Codabar. Bar codes require the TCPDF PDF engine (see Reports and Forms Settings).

Each element has its own font, size, alignment, and color, and can optionally have a border and/or fill. Table-style blocks have separate styling for their header row.

A Form can also be configured to: mark a record as printed once the form is generated for it (to help avoid accidentally reprinting the same document), start a new page whenever a chosen field's value changes (useful for printing a batch of many records in one run, one per page), and serialize/number each printed copy.

Field processing

Individual fields can be transformed as they're placed on a report or form: convert to uppercase or lowercase, negate a number, spell out a number in words (for printing checks), round to two decimals, format as a date, format as a dollar or euro amount, show blank instead of "No", force a field blank, or show a duplicate/printed indicator. When combining several fields into one line (for example a full address from separate address fields), a text separator controls how they're joined: a space, double space, comma, comma-space, new line, semicolon-space, or simply dropped if the value is empty.

Security

A report or form can be restricted to specific users and/or specific groups, left open to everyone, or effectively hidden from all logins. The designer warns if you're about to save a report that nobody would be able to see.

Starting from a built-in template

Rather than building from scratch, starter report and form templates shipped with a module can be imported individually or in bulk — this is how modules provide their default/example reports and forms.
