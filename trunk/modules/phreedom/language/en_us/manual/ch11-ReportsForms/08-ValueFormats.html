Value Formats

A format says how a value should be printed — as money, as a date, in capitals. It changes how the value is drawn and never what is stored, so changing one is always safe: nothing about the underlying record is altered.

The same list is used in three places, and this page is the reference for all of them:

  • the Format column when you are editing a report;
  • the Format column of a form's line-item table;
  • the Format column of an address block's lines.

Leaving it empty

An empty format prints the value exactly as it is stored. There is no clever default. A price held as 12.5 prints as "12.5", not "12.50" and not "£12.50"; a date held as 2026-08-19 prints as "2026-08-19".

So for text an empty format is usually right, and for money and dates it is usually wrong. If an amount column is coming out looking like a bare number, a missing format is the first thing to check.

Money

FormatWhat it prints
posted_curMoney, in the currency the document was posted in, with that currency's symbol and decimal places. This is the one for prices and line totals on an invoice, order or statement.
null_pcurThe same, but a zero prints as nothing at all. Use it for a column that is often empty — a discount, a tax — so the page is not full of zeros.
def_curMoney in the company's own currency, whatever the document was posted in. Right for a total that is being reported rather than charged.
null_dcurThe same, with a zero printing as nothing.
dlrA dollar sign and two decimals, regardless of the company's currency.
null-dlrThe same, with a zero printing as nothing. Note the hyphen: this one is null-dlr where its neighbours above are null_pcur and null_dcur with underscores. It is an inconsistency inherited from the older designer, and exactly the kind of misspelling that fails in silence.
euroA euro sign and two decimals, regardless of the company's currency.

dlr and euro come from the older designer and fix the symbol into the form. Prefer the four above them: those follow the currency, so one invoice layout serves every customer you bill.

Numbers

FormatWhat it prints
rnd_decA number to the currency's normal number of decimal places. The usual choice for a quantity.
rnd_preA number to the currency's precise number of decimal places, which is more than the normal one. Use it for a unit price that carries more decimals than the total does.
rnd2dRounded to two decimals, with no symbol and no thousands separator.
negFlips the sign. Useful where a value is stored one way round and read the other — a credit shown as a positive figure.
n2wrdThe number spelled out in words. This is what writes "One thousand two hundred and thirty" on a cheque.

Dates and text

FormatWhat it prints
dateThe date in the format this installation uses, rather than the way the database stores it.
ucThe text in capitals.
lcThe text in lower case.
blankNothing at all. A way to keep a column in place while stopping it printing.

Codes turned into words

Several values are stored as a code and mean nothing to the reader as they stand. These formats turn them into the words they stand for.

FormatWhat it prints
termsPayment terms, written out — "Net 30 days" rather than the stored code.
ship_nameThe name of the shipping method, rather than its internal identifier.
j_descThe name of the journal a transaction belongs to, from its number.
yesBno"Yes" when the value is set, and nothing when it is not.
NewUsed"Used" or "New".
printedNothing if the document has been printed before, and "Duplicate" if it has not. This is what puts the Duplicate mark on a reprinted document.
coa_typeThe name of an account type, from its number.
cvt_iso2A country's two-letter code, from the three-letter code stored against it — GBR becomes GB.
cvt_cntryA country's name, from the three-letter code stored against it — GBR becomes United Kingdom.

Choosing one

The Format box is a list you pick from, grouped under the same headings this page uses, so there is nothing to spell and nothing to remember. Each entry is described by what it does, with its stored name in brackets — that name is what you will see in an older definition, and what this page is organised by.

The first entry, As stored, is the empty format, and it is the commonest answer: most columns are text and want nothing done to them.

If a document already uses a format the list does not offer — one of the five below, or something inherited from an older installation — it appears at the end of the list under Already used by this document, and stays selected. Nothing is lost by opening a document and saving it.

One thing that will catch you out

Five formats only work where the report itself supplies the answer. These are rep_id, branch, avg_cost, avg_total and ordr_qty. Each needs a database lookup rather than a rearrangement of the value in hand, so the print engine deliberately refuses to perform one and prints the value untouched. Typing rep_id into a column gets you the raw identifier, not the salesperson's name. Where a report already shows one of these properly, it is because the report was built to fetch it, and copying the format alone onto another column will not reproduce it.

This is why they are not in the list to choose from: a list is an offer, and choosing rep_id would promise a salesperson's name and deliver a number. They are shown only where a document already uses one.

Finding what a column already uses

The quickest answer to "what should this be?" is usually a document that already gets it right. Open a shipped invoice, look at what its amount column uses, and use the same. The formats mean the same thing in a report as they do on a form.
