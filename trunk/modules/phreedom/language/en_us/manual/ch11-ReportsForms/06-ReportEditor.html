Editing a Report

The report editor changes what a report shows: which columns appear and in what order, how the rows are grouped, sorted and filtered, and how the page is laid out. Open it from Tools → Reports (Forms) and click Edit beside a report.

That is the only way in, and deliberately so: the Reports list is the one list of reports, and Cancel in the editor returns you to it. (Forms are different — they are kept off the Reports list, so Tools → Form Layout is both their list and the way into the form designer.)

Editing requires the Forms — write a report permission, which is separate from the one that lets someone run a report. If you can run reports but see no Edit button, that is the reason; the permission is granted per role under Company → User Security.

Columns

Each row in the Columns table is one column of the finished report. The Field list offers everything the report's dataset provides and nothing else — a report drawn from customer transactions can reach customer and transaction fields, and cannot reach anything the dataset does not name. Use the arrows to reorder columns and the × to remove one.

Width is in millimetres. Leaving it empty lets the report choose, which is usually what you want; set it when a particular column needs more room than it is being given. Total adds that column up at each group break and at the end of the report.

Format says how the value should be printed — as money, as a date, in capitals. An empty one prints the value exactly as it is stored, which is right for text and wrong for an amount: a price held as 12.5 prints "12.5" until you give the column a money format. The full list is in Value Formats, and it is a list you choose from rather than something to type.

Grouping, sorting and filters

Grouping on a field breaks the report wherever that field's value changes and prints a total for the group. Show group totals only hides the individual rows and leaves just those totals, which turns a detailed report into a summary one.

Filters decide which rows appear at all. Pick a field, pick a comparison, and give it a value. A few comparisons behave differently from the rest:

  • is one of takes several values separated by commas.
  • is between uses both value boxes.
  • is empty and is not empty need no value.

Some reports carry a filter that compares one column with others — the re-order worksheet asks for stock below its minimum plus what is already on order. Those are shown but cannot be changed here; they are left exactly as they are when you save.

Dates covered

Dates covered is the period the report defaults to when someone runs it, and Date range applies to is the field that period is measured against. A report about invoices usually measures the invoice date; one about payments, the payment date.

The preview

The preview on the right renders the report exactly as it will print, using your real data and including changes you have not saved yet. It does not refresh by itself — click Refresh the preview when you want to see the effect of what you have changed. A large report over several years takes a few seconds.

If the preview says the report returned no rows, the filters or the dates covered are excluding everything. That is worth resolving before saving.

Saving

Saving rewrites the report in the Forms format. If the report was still stored in the older format you will see a note saying so before you save: after saving, the original print engine can no longer open that report, and a copy of the original file is kept alongside it in case you need to go back. Reports you never edit are untouched and keep working in both engines.

The editor only saves what it can show you. If a field name is not one the dataset offers, it is not saved and you are told which one and why — a report that quietly keeps a column it cannot fill is worse than one that tells you.
