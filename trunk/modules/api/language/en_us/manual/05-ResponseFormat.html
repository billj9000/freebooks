REST API — Response Format & Errors

Success response

All successful responses return HTTP 200 with Content-Type: application/json; charset=utf-8:

{
  "ok": true,
  "data": [ ... ],
  "meta": {
    "limit_start":       0,
    "limit_page_length": 100,
    "count":             5,
    "total":             42
  }
}
KeyDescription
oktrue on success
dataArray of result objects. Each object has one key per requested field. Virtual fields containing nested arrays (e.g. lines, addresses) appear as JSON arrays within each row object.
meta.limit_startOffset of the first record returned (echoes the request parameter)
meta.limit_page_lengthMaximum records per page (echoes the effective value after clamping)
meta.countNumber of records in this response (may be less than limit_page_length on the last page)
meta.totalTotal number of records matching the filters across all pages

Error response

{
  "ok": false,
  "error": "Human-readable error message"
}

The HTTP status code indicates the error category (see table below).

HTTP status codes

CodeMeaningCommon causes
200OKRequest succeeded; data and meta are present
400Bad RequestMissing or invalid v parameter; unknown or non-filterable/non-sortable field; unknown operator; malformed JSON in fields, filters, or or_filters; invalid date format; empty in array
401UnauthorizedMissing Authorization header; invalid API key; key is disabled; key has no associated company
403ForbiddenRequest was made over HTTP and HTTPS is required
404Not FoundUnknown resource value; the error message lists available resources
405Method Not AllowedRequest used a method other than GET (the v1 API is read-only)
500Internal Server ErrorUnexpected server-side error; no details are leaked in the response
503Service UnavailableCompany configuration not found or database unavailable

All values are strings

All scalar values in data are returned as JSON strings, including numeric and date fields. This matches the underlying database representation and avoids precision loss with large decimal values. Parse numbers and dates as needed in your client.

Paging

To determine if there are more pages:

meta.limit_start + meta.count < meta.total

Advance the offset by limit_page_length each page until this condition is false.

Character encoding

All responses are UTF-8. Non-ASCII characters in data (e.g. accented letters, currency symbols) are returned as literal UTF-8, not as JSON Unicode escapes.

Future API versions

New API versions will be introduced via the v parameter (e.g. v=2). Version 1 will continue to be supported after new versions are released. The ok/data/meta envelope shape will remain consistent across versions.

Write operations (POST, PATCH, DELETE) are planned for a future version. They will use the same Bearer token authentication and will require keys with write scopes.
