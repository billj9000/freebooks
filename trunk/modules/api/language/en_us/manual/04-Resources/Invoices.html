REST API — Invoices Resource

resource=invoices

Returns Sales Invoices (journal J12) from journal_main. The base filter journal_id = 12 is always applied automatically; callers cannot override it.

Default fields (when fields is omitted)

id, invoice_number, reference, date, customer_id, customer_name, total, tax, freight, currency, closed

Note on the modified field

The journal_main table does not store a row-level last-modified timestamp. The modified field maps to post_date (the invoice date). This is sufficient for date-range export (e.g. “all invoices dated in June”) but does not detect invoices edited after their original posting date. If precise change tracking is required, use the date field for range filters.

Virtual field: lines

Include "lines" in the fields array to receive the product line items for each invoice as a nested array. Summary rows (tax, freight, discount, totals) are excluded; only product lines are returned.

Each line item object contains:

KeyDescription
skuInventory SKU / product code
descriptionLine item description as it appears on the invoice
qtyQuantity (float)
unit_priceUnit price, computed as amount / qty (6 decimal places)
amountExtended line total (unit_price × qty)
gl_accountGeneral ledger income account code
taxableTax rate ID (0 = non-taxable) — not a percentage; see tax_rate below
tax_ratetaxable resolved to a percentage — see note below

Line items are loaded in a single batch query for the entire page — no N+1 performance impact.

Note on tax_rate / freight_tax_rate

taxable and freight_taxable are tax_rate_ids, not percentages — a tax_rate_id can combine multiple tax authorities. tax_rate and freight_tax_rate resolve them to the actual percentage FreeBooks would use to calculate tax (summing tax_rates.rate_accounts against tax_authorities.tax_rate, the same calculation as gen_calculate_tax_rate()), so callers don't need to duplicate that lookup or hardcode rates that could drift out of sync.

Important: use freight_taxable, not freight_tax_id, if you need the tax rate ID that actually applied to freight. freight_tax_id is the raw per-order override on the order form and is commonly left at 0 (“use the company default,” AR_ADD_SALES_TAX_TO_SHIPPING) — the effective id FreeBooks used is only recorded on the posted freight line itself, which is what freight_taxable (and freight_tax_rate) resolve from.

Note on payment_reference

payment_reference is not journal_main.purch_order_id on the invoice itself — that's the reference field above, the customer's PO number. It's the payment processor's own reference (transaction ID, cheque number, etc.) recorded on the Cash Receipt (J18) that paid this invoice. An invoice can have more than one receipt against it (partial payments); the most recent receipt with a non-blank reference is used. Blank if the invoice hasn't been paid yet, or was paid with no reference recorded.

Example: export invoices for a date range

fields=["invoice_number","date","customer_id","customer_name","total","tax","freight","currency","currency_rate","closed","lines"]
filters=[["date","between",["2026-06-01","2026-06-30"]]]
order_by=date asc

Example: unpaid invoices over £1,000

fields=["invoice_number","date","customer_name","total","currency"]
filters=[["closed","=","0"],["total",">=","1000"]]
order_by=total desc

Example: invoices for a specific customer

filters=[["customer_id","=","42"]]
order_by=date desc
