REST API — Query Language

All query parameters are passed as URL query-string parameters. JSON-valued parameters (fields, filters, or_filters) must be valid JSON and should be URL-encoded when the URL contains special characters.

fields

A JSON array of public field names to include in the response. If omitted, the resource returns its default field set.

fields=["id","primary_name","email","telephone1"]

Unknown field names produce a 400 error. Order in the array does not affect SQL but does affect the key order in JSON output.

filters

A JSON array of filter triples [field, operator, value], all combined with AND.

filters=[["type","=","c"],["inactive","=","0"],["email","is set",""]]

Rules:

  • Each triple is [field, operator, value]. The field must be marked filterable in the resource’s field map.
  • Multiple filters are AND’d together.
  • For in and not in, the value must be a JSON array: ["c","v"].
  • For between, the value must be a 2-element JSON array: ["2026-01-01","2026-06-30"].
  • For is set and is not set, the value is ignored (pass "").

or_filters

A JSON array of filter triples in the same format as filters, but all conditions are OR’d together. The resulting OR group is then AND’d with the filters conditions.

filters=[["type","=","c"]]&or_filters=[["city","=","London"],["city","=","Manchester"]]

This produces: WHERE (type='c') AND (city='London' OR city='Manchester')

order_by

A single field name followed by asc or desc (case-insensitive). The field must be marked sortable in the resource field map. Default is no ordering (database natural order).

order_by=primary_name asc
order_by=date desc

limit_start

Zero-based offset for the first record to return. Default is 0. Use with limit_page_length to page through results.

limit_page_length

Maximum number of records to return in one response. Default is 100. Maximum is 500. The meta.total field in the response gives the total matching record count regardless of pagination.

Paging through results

# Page 1
?v=1&resource=contacts&filters=[["type","=","c"]]&limit_start=0&limit_page_length=100

# Page 2
?v=1&resource=contacts&filters=[["type","=","c"]]&limit_start=100&limit_page_length=100

Continue until meta.limit_start + meta.count >= meta.total.

Incremental sync (modified-since)

The contacts resource exposes a modified field (maps to the record’s last-update timestamp). Use a >= filter to fetch only records changed since your last sync:

filters=[["modified",">=","2026-07-01"]]

The invoices resource does not have a row-level modified timestamp; its modified field maps to post_date (the transaction date). Use date-range filters on date for incremental invoice export.

Type coercion

Filter values are cast according to the field’s declared type before being escaped and inserted into the query:

  • int fields: value must be numeric; cast to integer.
  • float fields: value must be numeric; cast to float.
  • date fields: value must match YYYY-MM-DD; non-conforming values produce a 400 error.
  • string fields: passed through as-is (after SQL escaping).
