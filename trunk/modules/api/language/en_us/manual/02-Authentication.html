REST API — Authentication & Key Management

How authentication works

Every request must carry the API key as a Bearer token in the HTTP Authorization header:

Authorization: Bearer fbk_live_your_key_here

On the server side, FreeBooks hashes the token with SHA-256 and looks it up in the api_keys table. Only the hash is stored — the plaintext key is never persisted after the generation dialog is closed. If the key is found and enabled, the associated company database is selected and the request proceeds.

Security properties

  • HTTPS required. Requests over plain HTTP are rejected with HTTP 403 unless the server has FREEBOOKS_API_ALLOW_HTTP=1 set in its environment (development only).
  • Keys are company-scoped. A key generated while logged into company A cannot access company B’s data.
  • Keys are one-time viewable. The plaintext is shown once in the generation dialog and is never stored or recoverable. If a key is lost, delete it and generate a new one.
  • Keys are revocable instantly. Revoking a key takes effect on the next request — there is no session caching.

Managing keys

Go to Company → Configuration → REST API. The page lists all keys for the current company with their label, key prefix (first few characters), scopes, enabled state, creation date, and last-used date.

Generating a key

  1. Click Generate New Key.
  2. Enter an optional label to identify what this key is used for (e.g. Phone System, Invoice Export).
  3. Click Generate New Key in the dialog.
  4. The plaintext key is displayed once. Click Copy to copy it to the clipboard. Click Close when done — the key cannot be retrieved again.

Revoking a key

Click Revoke next to the key. The key remains in the list (marked disabled) so you can re-enable it later. Any client using a revoked key immediately receives HTTP 401.

Re-enabling a key

Click Enable next to a revoked key.

Deleting a key

Click Delete and confirm. The key record is permanently removed. Requires security level 3 (administrator).

Key prefix

The table shows the first few characters of each key (e.g. fbk_live_9f2c…). This prefix is safe to log or display; it cannot be used to authenticate. Use it to identify which key a client is using when you see it in logs.

Scopes

Each key records a scopes field (currently contacts:read,invoices:read for all keys). Scope enforcement will be used by future API versions to restrict individual keys to specific resources or operations. Existing keys are forward-compatible.
