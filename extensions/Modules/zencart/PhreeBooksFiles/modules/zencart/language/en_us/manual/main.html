ZenCart Module

The ZenCart module integrates FreeBooks with a ZenCart e-commerce store. It provides two-way synchronisation:

  • ZenCart → FreeBooks: imports orders as Sales Orders, optionally with linked Sales Invoices and Cash Receipts
  • FreeBooks → ZenCart: uploads product data, syncs stock quantities and prices, confirms shipments

Installation

ZenCart side

Copy freebooks-zencart.php (from the zencart-api repository) to your ZenCart web root (the same directory as ZenCart's index.php). Then insert an API key into the ZenCart configuration table:

INSERT INTO configuration
  (configuration_title, configuration_key, configuration_value,
   configuration_description, configuration_group_id, sort_order, date_added)
VALUES
  ('FreeBooks API Key', 'FREEBOOKS_API_KEY', '<your-key>',
   'Secret key for FreeBooks ERP integration', 1, 100, NOW());

Generate a strong key with: php -r "echo bin2hex(random_bytes(32));"

FreeBooks side

Copy PhreeBooksFiles/modules/zencart/ into trunk/modules/. The module will appear under Tools → ZenCart and Company → Configuration → ZenCart after the next page load.

Go to Company → Configuration → ZenCart to set up the connection and import options.

Order Import (ZenCart → FreeBooks)

Orders are imported automatically at the end of each cron run. To run manually:

php /var/www/html/cron/zencart_sync.php

For each new ZenCart order the cron creates:

  1. A Sales Order (journal 10) — always
  2. A Sales Invoice (journal 12) — only when “Create invoice” is Yes
  3. A Cash Receipt (journal 18) — automatically when an invoice is created and a payment amount is present

The ZenCart order ID is stored as ZC-{id} in the Sales Order's PO reference field, so re-running the cron is safe — already-imported orders are skipped.

Customer matching

Each order is matched to an existing FreeBooks customer contact by email address. If no match is found, a new contact is created automatically from the billing address. If contact creation fails and a catch-all customer ID is configured, the order is assigned to that contact instead; otherwise the order is skipped.

Tax handling

ZenCart supplies a VAT percentage for each product line. The cron maps this to the nearest whole-number FreeBooks tax rate ID. If no match is found, the fallback tax rate ID is used. Do not rely on the item_taxable flag in inventory — FreeBooks defaults it to 0, which would strip VAT from every recognised SKU.

Rounding adjustment

If FreeBooks' calculated total differs from the ZenCart paid amount by between £0.001 and £0.99, a zero-tax line item with SKU ROUNDING is added automatically so both systems show the same total.

Discounts and coupons

ZenCart coupon discounts arrive as a line item with SKU Discount. The absolute discount amount is applied to the Sales Order's discount field.

VAT mismatch warning: FreeBooks by default calculates VAT on the pre-discount subtotal, while ZenCart calculates VAT on the post-discount amount. For orders with coupons, FreeBooks and ZenCart totals will differ by VAT rate × discount amount (e.g. £2.00 on a £10 coupon at 20% VAT).

To make FreeBooks match ZenCart's totals, go to PhreeBooks Admin → Customers tab and set:

  • Enable percent/value discounts on order totals → Yes
  • Calculate Customer Sales Tax Before Discount Applied → After Discount

Discount percentage display: FreeBooks back-calculates the displayed discount percentage as discount ÷ (products + shipping subtotal). Because shipping is carried as a product line (see below), a product-only coupon will display as a slightly lower percentage than expected. The monetary amounts are correct.

Shipping

The ZenCart shipping line (SKU Shipping) is mapped to the freight field on the Sales Order. The tax rate is taken from ZenCart's shipping tax percentage and mapped to a FreeBooks tax rate ID, allowing shipping to carry a different VAT rate than the products. (FreeBooks' built-in freight field uses a single global freight tax rate and cannot carry a per-order rate, which is why shipping is handled this way.)

Payment module map

The payment module map tells FreeBooks which payment method and GL account to use for each ZenCart payment module. Format:

zcmodule=fbmodule:glacct, ...

Example: paypalexpress=paypal_nvp:1020, stripe=freecharger:1030

Either part may be omitted (e.g. paypalexpress=paypal_nvp or stripe=:1030). Unmapped modules use freecharger with the default cash account.

Product Upload (FreeBooks → ZenCart)

Single product upload

From the Inventory list, select a product and use the ZenCart Upload toolbar button. The product's details, price, and image are sent to ZenCart.

Bulk upload

From Tools → ZenCart, click Bulk Upload to upload all inventory items that have the catalog checkbox set. Tick Include Images to include product images.

Quantity sync

The Synchronize button (and the cron) pushes current stock quantities and prices to ZenCart for all catalog items:

  • Items with multiple quantity price tiers are uploaded individually so ZenCart receives the full tier structure and can display quantity discounts.
  • All other items are sent in a single bulk API call.

Price sheets and quantity discounts

When Use price sheets is Yes and a price sheet is selected, each item's price is calculated from that sheet. Items with more than one active quantity tier are uploaded as full products, writing tier rows to ZenCart's products_discount_quantity table so quantity discounts appear on the product page.

If no global price sheet is configured, the module falls back to the item-level price_sheet field on each inventory record.

Shipment Confirmation

From Tools → ZenCart, select a date and click Confirm Shipments. The module reads the FreeBooks shipping log for that date and posts a comment to the matching ZenCart orders containing the carrier, method, and tracking number. Fully shipped orders receive the Shipped status; partially shipped orders receive the Partial status.

Cron Setup

Add to crontab (adjust path as needed):

*/15 * * * * php /var/www/html/cron/zencart_sync.php >> /var/log/zencart_sync.log 2>&1

The script is safe to run frequently — it only imports orders with IDs higher than the last imported order ID and always runs a stock quantity sync at the end.
