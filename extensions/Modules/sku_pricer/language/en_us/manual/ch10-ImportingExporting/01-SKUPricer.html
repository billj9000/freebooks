SKU Price Importer

The SKU Price Importer updates prices, costs and other details on inventory items you already have, from a CSV file. It is reached from the Inventory → SKU Pricer menu, and is part of the optional SKU Pricer module.

It only ever updates. It never creates an item. A row whose SKU is not already in your inventory matches nothing and is passed over in silence. To add new items, use the inventory import described in Importing/Exporting.

Before you start

  1. Take a backup. The importer writes directly to your inventory and there is no preview and no undo.
  2. Try a few rows first. The importer applies each row as it reads it, so a file that fails part way through leaves the rows before that point already applied.

The file

A comma-separated file whose first row is a header naming the columns. The header is what decides which fields are written: a column you leave out of the file is left alone on the item, so a file containing only sku and full_price changes prices and nothing else.

Every row must identify an item, using one of:

  • sku — the item's SKU. Used whenever it is present and not empty.
  • upc_code — used only when there is no sku column, or the SKU on that row is empty.

If a row offers neither, the import stops at that row with the message "No search field was found". Rows already processed stay applied; rows after it are not read.

Columns you can include

Anything outside this list is ignored, so a spreadsheet exported from elsewhere can carry extra columns without harm.

The item's last updated date is set to today on every row that matches.

Purchasing details

Five of those columns — description_purchase, price_sheet_v, purch_taxable, item_cost and vendor_id — also update the item's purchasing record, which is what the Vendors tab of an inventory item shows.

Include vendor_id and only that vendor's purchasing record is updated. Leave it out and every vendor record for the item is updated together, which is rarely what is wanted for an item bought from more than one supplier.

Running it

  1. Go to Inventory → SKU Pricer.
  2. Choose the CSV file.
  3. Press the Save icon.

Reading the result

The importer reports "Total lines processed: N. Total affected rows = M."

N and M are not expected to match, and a gap does not by itself mean something failed. M counts rows the database actually changed, so a row is left out of it when the SKU was not found and when the values in the file were already the values on the item. If M is lower than you expect, check a few of the SKUs exist and are spelled as they are in FreeBooks before assuming the file was wrong.
